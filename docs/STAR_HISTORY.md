## What matters more than stars

If you found XIR useful, these are worth more:

- **[Open an issue](https://github.com/ZakLr/XIR/issues)** when a model says something
  wrong. Wrong answers are the bug class that matters here, and I cannot find them
  without reports.
- **[Ask a question](https://github.com/ZakLr/XIR/discussions)** that the docs did not
  answer. A doc gap is a real defect.
- **Model something real** and tell me what broke. The five bundled examples are small
  and clean on purpose; real products are where the ontology gets tested.
- **Argue with the design** in
  [Discussions](https://github.com/ZakLr/XIR/discussions). The strongest case so far
  against this project is that a well-organised repository is good enough. If you can
  show that, say so.

## Honest framing

XIR has no adoption data yet. It is a young project with a real implementation, a real
spec, and one benchmark suite that labels every claim `MEASURED`, `SIMULATED` or
`INFERRED`. It has **not** been shown to make an LLM agent faster or more correct —
no blinded trial has been run. That is the first item on
[the roadmap](ROADMAP.md), and I would rather say so than let a star count imply
otherwise.
